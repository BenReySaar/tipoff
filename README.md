# טיפ-אוף · מדריך העלאה לאוויר

המדריך הזה לוקח את הקוד שבמאגר הזה ב־GitHub לאפליקציה חיה שהורים פותחים בטלפון, עם התראות, יומן מתעדכן ודף נתוני שימוש.
הכל נעשה דרך לוח הבקרה של Cloudflare בדפדפן. לא צריך להתקין שום דבר במחשב. בפעם הראשונה זה לוקח בערך 20 דקות.

אחרי ההתקנה, **כל שינוי שנשמר במאגר עולה לאוויר לבד** תוך דקה או שתיים.

---

## מה יש במאגר

| קובץ / תיקייה | מה זה |
|---|---|
| `public/` | האפליקציה עצמה: מה שההורה רואה בטלפון |
| `src/` | השרת: מושך את הלוח מהאיגוד כל שעה, מזהה שינויים, שולח התראות, יומן ונתוני שימוש |
| `wrangler.toml` | הגדרות. יש בו 2 ערכים שכתוב בהם `FILL` (סעיף 2) |
| `tools/browser-sync.js` | תוכנית ב׳ אם אתר האיגוד חוסם את השרת (סעיף 8) |
| `public/privacy.html`, `public/accessibility.html` | טיוטות של מדיניות פרטיות והצהרת נגישות. צריך למלא בהן את החלקים בסוגריים מרובעים |

## כמה זה עולה

| מה | מחיר |
|---|---|
| Cloudflare Workers Paid | 5 דולר לחודש (כ־19 ₪). הכרחי: בתוכנית החינמית שרת יכול לבצע רק 50 בקשות בכל ריצה, והסנכרון צריך כ־160 |
| כתובת משלך (לא חובה בהתחלה) | כ־60–100 ₪ לשנה ל־‎.co.il |
| GitHub | חינם |

עד עשרות אלפי משתמשים זה המחיר. מעבר לזה Cloudflare גובה תוספת קטנה לפי שימוש.

---

## 1. חשבון ותוכנית

1. נרשמים ל־Cloudflare: https://dash.cloudflare.com/sign-up
2. בלוח הבקרה: **Workers & Pages** ← **Plans** ← בוחרים **Workers Paid**. צריך כרטיס אשראי.

## 2. מסד נתונים ואחסון (פעמיים "Create")

1. בתפריט הצד: **Storage & Databases** ← **D1 SQL Database** ← **Create database**. שם: `tipoff`. אחרי היצירה מופיע **Database ID**. מעתיקים אותו.
2. בתפריט הצד: **Storage & Databases** ← **KV** ← **Create a namespace** (או Create instance). שם: `tipoff`. מעתיקים את ה־**ID** שלו.
3. את שני המספרים האלה מכניסים ל־`wrangler.toml`, במקום `FILL-d1-database-id` ו־`FILL-kv-namespace-id`. אפשר לערוך את הקובץ ישירות באתר של GitHub (אייקון העיפרון), או לשלוח אותם ל־Claude שיעדכן. הם לא סודיים.

את הטבלאות במסד הנתונים ואת המפתחות של ההתראות השרת יוצר לבד בפעם הראשונה שהוא רץ.

## 3. חיבור Cloudflare למאגר ב־GitHub

1. **Workers & Pages** ← **Create** ← **Import a repository** (או Connect to Git).
2. מחברים את חשבון GitHub ומאשרים גישה למאגר `tipoff`.
3. בוחרים את המאגר `tipoff`. בהגדרות הבנייה:
   - **Project name:** `tipoff`
   - **Build command:** משאירים ריק
   - **Deploy command:** `npx wrangler deploy`
4. לוחצים **Deploy**. בסוף מופיעה כתובת כמו `https://tipoff.<השם-שלך>.workers.dev`. **זו כתובת האפליקציה.**

## 4. סיסמה לדף נתוני השימוש

1. **Workers & Pages** ← `tipoff` ← **Settings** ← **Variables and Secrets** ← **Add**.
2. Type: **Secret**. Name: `ADMIN_KEY`. Value: סיסמה ארוכה שתבחרי (לפחות 20 תווים). שומרים אותה במקום בטוח.
3. **Deploy** / שמירה.

## 5. הסנכרון הראשון

השרת מושך את הלוח מאתר האיגוד אוטומטית בכל שעה, בדקה 7. מחכים לדקה 7 הבאה.

## 6. בדיקה

1. פותחים בדפדפן: `https://<הכתובת שלך>/stats?key=<הסיסמה מסעיף 4>`
2. בתחתית הדף, תחת **סנכרון מול אתר האיגוד**, צריך להופיע **תקין** ומספר המשחקים (כ־15,000).
3. פותחים את הכתובת בטלפון, בוחרים קבוצה, מוסיפים למסך הבית, ובמסך **התראות** לוחצים **הפעלת התראות** ואז **שליחת התראת בדיקה**.

## 7. שינויים בהמשך

כל שינוי שנשמר בענף `main` במאגר עולה לאוויר לבד. אפשר לבקש מ־Claude לבצע שינוי ולשמור אותו במאגר, או לערוך קובץ ישירות באתר של GitHub. אם שינוי שבר משהו, ב־Cloudflare ← `tipoff` ← **Deployments** אפשר לחזור לגרסה קודמת בלחיצה.

## 8. אם הסנכרון נכשל (תוכנית ב׳)

אם בדף הנתונים מופיע **נכשל** ו"אתר האיגוד חסם את השרת", אפשר לשלוח את הנתונים מהדפדפן שלך, כמו שעשינו בפעם הראשונה:

1. פותחים את `tools/browser-sync.js` ומחליפים בו את שתי השורות העליונות: הכתובת שלך והסיסמה מסעיף 4.
2. פותחים את https://ibasketball.co.il בכרום, לוחצים F12 ← Console.
3. מדביקים את כל הקובץ ולוחצים Enter. תוך כדקה תופיע הודעה עם מספר המשחקים.

כל ההתראות על שינויים עובדות גם בדרך הזו. החיסרון: זה קורה רק כשמריצים את הסקריפט, ולא כל שעה. אם זה המצב לאורך זמן, זה הזמן לפנות לאיגוד.

## 9. כתובת משלך (כשמוכנים)

1. קונים כתובת ‎.co.il אצל רשם ישראלי (למשל LiveDNS, Box, domainthenet).
2. ב־Cloudflare: **Add a domain**, ומעדכנים אצל הרשם את שרתי ה־DNS לאלה ש־Cloudflare נותנת.
3. ב־Workers & Pages ← tipoff ← Settings ← **Domains & Routes** ← Add ← Custom domain.
4. זהו. אין צורך לשנות קוד: האפליקציה משתמשת בכתובת שממנה היא נפתחה.

שימו לב: מי שכבר הוסיף את האפליקציה למסך הבית מהכתובת הקודמת יצטרך להוסיף אותה שוב. לכן עדיף לעבור לכתובת משלך לפני שמפיצים להרבה הורים.

## איך יודעים כמה אנשים משתמשים

דף הנתונים: `https://<הכתובת שלך>/stats?key=<הסיסמה>`. כדאי לשמור אותו כסימנייה.

| מה רואים | מה זה אומר |
|---|---|
| **פעילים היום / ב־7 ימים / ב־30 ימים** | כמה מכשירים פתחו את האפליקציה |
| **מכשירים בסך הכל** ו**עם קבוצה לפחות** | כמה הגיעו, וכמה באמת בחרו קבוצה |
| **התראות פעילות** | המדד הכי חשוב: מי שהפעיל התראות קיבל ערך אמיתי |
| **הוסיפו למסך הבית** | מי שהתקין את האפליקציה |
| **חוזרים** | מכשירים מלפני שבוע ויותר שנכנסו שוב השבוע |
| **מה עושים באפליקציה** | ניווטים, שיתופים, חיבור יומן ועוד |
| **התראות** ו**שינויים שזוהו** | כמה שינויים בלוח השרת תפס, וכמה התראות יצאו |
| **הקבוצות והמועדונים הכי נעקבים** | איפה האפליקציה תפסה, ולאיזה מועדון כדאי לפנות |

"משתמש" הוא מכשיר. הורה עם טלפון ומחשב נספר פעמיים. השרת לא שומר שמות, טלפונים או אימיילים, רק מזהה אקראי שנוצר בטלפון.

## עדכונים שגרתיים

- **עונה חדשה (פעם בשנה, באוגוסט–ספטמבר):** משנים את `SEASON = "2026"` ל־`"2027"` ב־`wrangler.toml`.
- **חשבונות ברשתות החברתיות:** ב־`public/index.html` מחפשים `const SOCIAL=` ומכניסים את הקישורים, למשל `['אינסטגרם','https://instagram.com/...']`.
- **כל שינוי בקוד:** נשמר במאגר ועולה לבד (סעיף 7).

## לפני שמפיצים להורים

- [ ] למלא את החלקים בסוגריים מרובעים ב־`privacy.html` וב־`accessibility.html`. מומלץ שעורך דין יעבור על מדיניות הפרטיות.
- [ ] לבדוק התראה אמיתית באייפון ובאנדרואיד (סעיף 7).
- [ ] לחבר יומן באייפון ולוודא שהמשחקים מופיעים.
- [ ] להחליט על כתובת קבועה (סעיף 9).

## אם משהו לא עובד

| מה רואים | מה עושים |
|---|---|
| "לא הצלחנו לטעון את לוח המשחקים" | הסנכרון הראשון עוד לא רץ. מחכים לדקה 7 של השעה הבאה, או משתמשים בתוכנית ב׳ |
| ההעלאה ב־Cloudflare נכשלה | בדרך כלל ה־ID של D1 או KV לא הועתק נכון ל־`wrangler.toml` (סעיף 2) |
| באייפון אין כפתור התראות | צריך להוסיף למסך הבית מספארי ולפתוח משם. נדרש iOS 16.4 ומעלה |
| הסנכרון נכשל עם "נעצר כדי לא לשמור נתונים חסרים" | השרת קיבל הרבה פחות משחקים מבפעם הקודמת, ולכן לא דרס את הנתונים. בדרך כלל זו תקלה זמנית באתר האיגוד, והשעה הבאה תסתדר |
| דף הנתונים מחזיר "לא נמצא" | הסיסמה בכתובת לא תואמת ל־`ADMIN_KEY` (סעיף 4) |

### נספח: העלאה משורת הפקודה (למפתחים)
```
npm install
npx wrangler login
npx wrangler d1 create tipoff          # ה־id ל־wrangler.toml
npx wrangler kv namespace create KV    # ה־id ל־wrangler.toml
npx wrangler secret put ADMIN_KEY
npx wrangler deploy
```
